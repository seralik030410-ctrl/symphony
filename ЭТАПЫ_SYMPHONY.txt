SYMPHONY 2.0 — КРАТКО ПО ЭТАПАМ
Состояние на 01.09.2026. Основа: docs/SYMPHONY_2_REBUILD_SPEC.md.
По спецификации всего 8 этапов: от 0 до 7.

0. Чистый старт — ГОТОВО.
   Новая отдельная папка, структура backend/frontend, копия спецификации.
   Старое приложение не изменяем.

1. Обычный чат — ГОТОВО.
   FastAPI + React/TypeScript, Ollama и OpenAI-compatible API.
   Независимые чаты и turns, потоковый ответ, Stop, SQLite-события,
   восстановление после обновления страницы и изоляция контекста.

2. Инструменты — ГОТОВО.
   Единый цикл «модель → инструмент → результат».
   Чтение, запись, patch и поиск файлов; журнал реальных действий,
   таймауты, отмена и Retry.

3. Sandbox для кода — ГОТОВО.
   Python и Node.js в Docker, постоянный workspace каждого чата.
   Команды, тесты, build, встроенное preview, разрешения и подтверждения.
   Также: вкладки файлов и diff, снимки, восстановление, корзина чатов,
   прокрутка, скрытие панелей и запуск через START.bat.

4. Skills 2.0 — ГОТОВО.
   Установка из папки/ZIP/Git, настройки, редактор, удаление и восстановление.
   Режимы Explicit/Auto/Always/Off, проверка активации, чтение по необходимости.
   Скрипты — только через инструмент, с подтверждением и в Docker.
   Установлены 31 ваш уникальный skill + 1 встроенный пример.

5. Документы — ГОТОВО.
   Структурные описания PDF, XLSX, DOCX и PPTX; готовые надёжные рендереры.
   Версии результатов, проверки, preview страниц и таблиц, скачивание.
   Главная проверка: PDF/XLSX создаются без написания рендерера моделью.
   Есть карточки в чате, вкладки рядом с чатом, загрузка XLSX/CSV,
   изоляция документов между чатами и отмена без ложного результата.

6. Контекст, поиск по файлам и изображения — ГОТОВО.
   Индекс файлов, выбор нужных фрагментов, структурированная память.
   OCR и передача изображений только совместимой vision-модели.
   Большие файлы не должны целиком попадать в каждый запрос.
   Настройки окна и лимита ответа уже добавлены в «Контекст и память».
   Автоматическое смысловое сжатие через выбранную модель, версии и message IDs.
   Последние десять сообщений остаются дословными, исходная история хранится.
   Память можно просмотреть, отредактировать, очистить или сжать вручную.
   Вложения сохраняются после refresh и Retry; есть vision и локальный OCR.
   Приёмка и честные ограничения: docs/STAGE_6_STATUS.md.

7. Интернет и упаковка macOS — В РАБОТЕ, НЕ ЗАВЕРШЁН.
   Поиск и чтение страниц, ссылки на источники, сетевой allowlist.
   Tauri-приложение, Keychain, drag-and-drop, установщик,
   обновления и диагностика зависимостей на MacBook.
   Чтение сайтов/ссылки проверены на реальной Ollama. Поиск DuckDuckGo вернул HTTP 202.
   Desktop-код пока не скомпилирован. Системная тема и самостоятельная установка runtime
   без исходников готовы. Живой поиск и чтение источника прошли; остались сборка/подпись и приёмка на MacBook.

ИТОГ: этапы 0–6 закрыты по журналу реализации; этап 7 ещё требует реализации и проверок, не только приёмки.
Это не означает готовность всех возможностей из полного ТЗ.
Финальный прогон: backend 195 passed с Docker, без пропусков; frontend 42 passed; TypeScript и сборка успешны.
Первый прогон пропустил Docker: он не запускался из-за временного сокета dockerInference; позже движок снова стал доступен.
Образы и данные не сбрасывались. После возвращения Docker финальный полный прогон этапа 7 прошёл успешно.
Подробности и оставшиеся пункты: docs/STAGE_7_STATUS.md и IMPLEMENTATION_LOG.md.

ПРО УДАЛЕНИЕ skill_for_s
Ничего страшного для установленных навыков: это была исходная папка импорта.
Установщик скопировал навыки в data/skills/<id>, а не создал ссылки.
После удаления проверено: все 32 папки и их SKILL.md остались на месте.
Для резервной копии сохраняйте всю data, включая symphony.db и skills.
Повторный импорт по старому пути потребует снова скачать исходники
либо экспортировать установленный навык из настроек Symphony.
