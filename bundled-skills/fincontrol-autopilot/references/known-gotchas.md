# Известные технические ловушки этой конкретной книги

Всё ниже проверено эмпирически на `FinControl_Master_v1.xlsx` (не теория).
Эти правила **переопределяют** дефолтное поведение обычного xlsx-скилла там,
где они входят в противоречие.

## 1. НИКОГДА не гоняй эту книгу через обычный `recalc.py` (LibreOffice)

**Проверено:** запуск стандартного `scripts/recalc.py` (xlsx-скилл) на этой
книге даёт `status: errors_found`, **56 ячеек `#NAME?`**, все — в
`01_Справочники` (диапазоны строк 2 и 148-149). Причина: справочник
использует `=FILTER(...)` (`_xlfn._xlws.FILTER`) для динамических
spill-списков, которые формируют выпадающие списки (Data Validation) для
Project ID / Block ID / Counterparty ID / Material ID / Cost Code / Currency
/ Cash Account / Employee ID / Warehouse ID / BOQ Code по всей книге.
LibreOffice headless в этом окружении не умеет вычислять `FILTER`, а
openpyxl-запись убивает spill-metadata — в сумме получаешь книгу с
формально "пересчитанной" структурой, но **сломанными выпадающими списками
почти во всех операционных листах**.

Что делать вместо этого:
- Для чтения текущих значений — используй `data_only=True` (в файле уже есть
  кэшированные значения из реального Excel, они актуальны на момент
  последнего сохранения пользователем).
- Для проверки формул на ошибки — читай **кэшированные** значения-ошибки
  (`#REF!`, `#VALUE!` и т.д.), это и делает `scripts/audit_workbook.py`, без
  пересчёта.
- Если ты **обязан** внести и проверить правку формулы вне
  `01_Справочники!строки 2 и 148-158`: пиши формулу, читай её обратно
  (`data_only=False`) чтобы убедиться, что строка формулы верна, и проверяй
  результат точечно (вручную посчитай ожидаемое значение и сверь с логикой),
  а не через общий Full Calculate всей книги.
- Если правка требует настоящего пересчёта всей книги (сложная
  многоуровневая формула, которую нельзя проверить вручную) — предупреди
  пользователя явно: "чтобы безопасно пересчитать книгу, нужно на время
  завести статические копии FILTER-списков (`01_Справочники!H149:Q158`),
  пересчитать, затем вернуть формулы" — и не делай это молча.
- Список конкретных ячеек с FILTER — 19 штук, все в `01_Справочники`
  (диапазоны `I2:Q2` и `N148:Q148`, `H149:M149`) — можно всегда получить
  свежим списком через `scripts/audit_workbook.py` (`risky_functions.
  "_xlws.FILTER".cells`).

## 2. `OFFSET` в `08_Акты` (колонки Z, AL, AQ) — это фича, не баг

9 формул с `OFFSET` реализуют паттерн "растущий диапазон только по уже
проведённым строкам выше текущей" — то есть кумулятивный итог без обычного
`SUMIF($F$2:F2,...)`, потому что нужна фильтрация по третьему условию
(`Статус="Проведён"`) одновременно с растущим диапазоном. Формулы:

- `Z2` (Previous Approved Qty) — кумулятив по BOQ Code, только проведённые.
- `AL2` (Open Advance Before) — аванс по контракту минус кумулятивно
  применённое до этой строки.
- `AQ2` (Retention Balance cumulative) — накопленный retention minus release.

Это НЕ повод автоматически переписывать на что-то "менее volatile" — правило
101 из `principles.md` требует: сначала понять цель, построить безопасную
альтернативу, сравнить ВСЕ выходы, заменить только при нулевой разнице. При
малом числе строк (сейчас 3 акта) производительность не проблема; при росте
до сотен строк — стоит предложить пользователю миграцию на
`SUMIFS`-с-структурными-ссылками, но не делать это без спроса.

## 3. Циркулярная ссылка — не размещай сводки в колонках F/G/I/S листа `08_Акты`

Из `00_README` (Этап 6, дословное предупреждение автора книги): новые
сводные блоки на `08_Акты`, которым нужно читать `14_KS6a`, размещены **вне**
границ таблицы `tblActs` (в колонках BJ и правее). Причина: колонки
**F, G, I, S** листа `08_Акты` используются как whole-column критерии в
формулах `14_KS6a`, `13_BvA` и `Договоры` — если добавить туда (или в их
диапазон) формулу, которая сама зависит от `14_KS6a`, получится циркулярная
ссылка. Если нужно расширить сводки на Акты — добавляй колонки **после BH**
(конец текущей Table) или **после BJ+ блока**, никогда не вставляй столбцы
внутрь A:BH без проверки всех формул, ссылающихся на текущие буквы колонок.

## 4. `01_Справочники` — единственный источник ID, не создавай параллельные списки

Все выпадающие списки в операционных листах питаются от `01_Справочники`
через именованные диапазоны (`ActiveProjects`, `ActiveBlocks`,
`ActiveCounterparties`, `ActiveMaterials`, `ActiveCostCodes`,
`ActiveCurrencies`, `ActiveCashAccounts`, `ActiveEmployees`,
`ActiveWarehouses`, `ActiveBOQCodes`) — все они являются ANCHORARRAY-ссылками
на FILTER-формулы из п.1. Если нужно добавить новую сущность (проект,
контрагента, материал и т.д.) — добавляй строку в соответствующую Table в
`01_Справочники`, никогда не вводи ID вручную текстом в операционный лист в
обход справочника.

## 5. Всего 16 workbook-level именованных диапазонов

Большинство ссылок в книге идут через **структурные ссылки Excel Tables**
(`tblActs[Document ID]`), а не через Named Ranges. Не предполагай, что для
какой-то сущности существует Named Range — проверь в `openpyxl
wb.defined_names` (или `scripts/audit_workbook.py` → `named_ranges`) прежде
чем на него ссылаться.

## 6. Предупреждение openpyxl про Data Validation extension — ожидаемо, не чини

При загрузке книги через `openpyxl.load_workbook` появляется:
`UserWarning: Data Validation extension is not supported and will be removed`.
Это связано с современным форматом Data Validation (extLst), который
openpyxl не умеет полностью читать/писать. **Не пытайся "исправить" это** —
если ты сохранишь книгу через openpyxl без явной необходимости менять DV,
проверь после сохранения, что выпадающие списки в операционных листах
по-прежнему работают (открой файл в реальном Excel или спроси пользователя
проверить), т.к. эта ветка сохранения — ещё один канал потери DV помимо
FILTER-проблемы из п.1.

## 7. Формула-ошибки в файле на момент подготовки скилла: 0

Прогон `scripts/audit_workbook.py` на исходном файле дал 0 ошибок формул
(`#REF!`, `#NAME?` и т.д. в кэшированных значениях), 0 дублей ID, 0 внешних
ссылок, 47 Tables, 16 Named Ranges. Если увидишь другие цифры при следующем
запуске — значит, книга изменилась с момента подготовки этого скилла
(это нормально, просто ориентируйся на свежий прогон, а не на эти цифры).
